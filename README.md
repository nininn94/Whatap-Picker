# WhaTap Picker

> 오프라인 부스 리드 전환을 위한 AI 기반 이벤트 운영 자동화 시스템  
> *리드 획득을 향한 마케팅팀의 집착*

설문 수집부터 디지털 추첨, 경품 관리, AI 리드 분류, 마케팅 인사이트까지 하나의 플랫폼에서 처리합니다.

## 해결하려는 문제

WhaTap 오프라인 부스에서는 실물 뽑기판을 활용한 경품 이벤트를 반복 운영해왔습니다.  
참여율은 높지만, 세 가지 구조적 문제가 매 행사마다 반복됐습니다.

| 문제 | 원인 |
|------|------|
| **흩어진 도구** | 설문은 Tally/Google Forms, 추첨은 수기, 결과는 나중에 엑셀로 — 도구가 분리되어 인력이 필수로 투입됨 |
| **길어지는 대기 줄** | 설문 제출 → 중복자 체크 → 추첨 → 설문 기록 확인 → 경품 지급이 한 지점에서 순차 처리되어 부스 회전이 느려짐 |
| **데이터 누락과 오차** | 중복 참여, 재고 오차, 리드 누락으로 행사 후 정리에 추가 시간이 소요되고 영업 연결이 지연됨 |

## 활용한 AI 기술/도구

> **AI는 코드만 짠 게 아닙니다** — 개발 도구로도, 서비스 안에서도 두 축으로 활용했습니다.

### 개발 도구로 (AS A CODING TOOL)

| 도구 | 활용 내용 |
|------|-----------|
| **Claude Code** | 전체 아키텍처 설계, 기능 명세·API 초안 작성, Spring Boot 컨트롤러·서비스 코드 생성, 추첨·재고·일자별 제한 로직, 테스트 케이스·리팩터링 |
| **OpenAI Codex** | 모바일 설문·운영자 추첨 화면 UI 컴포넌트 생성, 프론트엔드 유틸리티 코드 초안 |

### 서비스 안에서 (IN THE SERVICE)

#### 1. 리드 Lifecycle Stage 자동 분류

설문 제출 시 **Rule Engine**이 응답 내용을 즉시 분석해 MQL / Known Lead를 결정합니다.

```
설문 제출 → LeadScoringPipeline (@Async, 비동기)
  └── RuleEngine.evaluate()
        ├── MQL 조건: 상담 희망(ONSITE_MEETING) 또는 도입 계획(연내 교체·신규 도입)
        └── 그 외 → Known Lead
        
미결 케이스 → LlmGateway
  ├── Ollama (로컬 CPU, qwen2.5:1.5b) — 외부 API 비용 없이 처리
  └── 실패 시 → Claude Haiku (Anthropic API) 폴백
```

비동기 처리로 설문 제출 응답 속도에 영향을 주지 않습니다.

#### 2. AI 마케팅 인사이트 자동 생성

어드민 대시보드에서 인사이트 생성 요청 시 **Claude Haiku**가 수집된 리드 통계를 분석해 자연어 리포트를 실시간 생성합니다.

- 관심 제품·도입 시기·직무·회사 맥락을 종합 분석
- 후속 액션 우선순위 자동 제시
- 영업·마케팅이 어디부터 손대야 할지 한눈에 파악

#### 3. 리드 유효성 자동 검증

AI 활용 이전 단계에서 데이터 품질을 코드 레벨로 확보합니다.

| 정책 | 구현 방식 |
|------|-----------|
| 전화번호 유효성 | 010 포함 11자리, 0000/1111 등 무효 패턴 원천 차단 (`PhoneNormalizer`) |
| 이메일 도메인 | 개인 메일 11종 자동 차단, 학생·프리랜서는 허용 (`LeadService`) |
| 중복 참여 제한 | 행사 일자별 1회 제한, phone+eventId unique 제약 (`Lead` 엔티티) |
| Rate Limiting | IP당 분당 10회 제한 (Bucket4j) |

## 결과물 소개

**WhaTap Picker**는 부스 운영자·방문자·마케팅 후속 액션이 같은 데이터를 보고 움직이도록 설계된 웹 기반 시스템입니다.

### 핵심 사용자 흐름

```
1. QR 설문       방문자가 모바일로 스캔 → 설문 제출
        ↓
2. 참여자 검색    이름 + 휴대폰 뒷 4자리로 즉시 조회
        ↓
3. 동명이인 식별  회사명을 노출하여 본인 선택
        ↓
4. 1일 1회 체크  행사 일자별 중복 참여 자동 차단
        ↓
5. 추첨 실행     일자별 정해진 경품 수량만큼 디지털 추첨
        ↓
6. 결과 노출     결과 화면 표시 = 지급 처리 자동 완료
        ↓
7. 재고 차감     추첨 결과에 따라 경품 재고 자동 업데이트
```

### 화면 구성

**① 모바일 설문 폼 (참여자)**
- QR 스캔으로 접근, 행사별 설문 질문 렌더링
- 개인 이메일·무효 전화번호 실시간 차단
- 제출 즉시 AI 리드 분류 및 Google Sheets 자동 기록 (비동기)
- 개인정보 동의 필수, 동명이인 검색 시 회사명만 추가 노출

**② 현장 뽑기판 (DrawBoard)**
- 행사장 대형 화면 상시 표시
- 이름 + 전화번호 뒷자리로 설문 제출자 본인 확인
- 디지털 추첨 애니메이션 → 등수 결과 표시
- 설문 미제출자·중복 참여자·재고 소진 각각 별도 안내

**③ 운영자 어드민**
- 행사 생성·QR 코드 발급 (PNG)
- 설문 폼 구성 및 행사별 폼 템플릿 관리
- 경품 등수별 재고 입력 → 추첨 시 자동 차감
- 수집 리드 조회·필터링·키워드 검색·CSV 내보내기
- AI 리드 분류 결과 확인 및 수동 재분류 (Override)
- 대시보드: 일자별 참여 현황, 리드 세그먼트, 경품 재고
- LLM 마케팅 인사이트 리포트 생성
- Google Sheets 행사별 자동 연동 설정

### 기술 스택

| 영역 | 기술 |
|------|------|
| 백엔드 | Java 21, Spring Boot 3.4, Spring Security 6.4, JPA, PostgreSQL 16, Flyway |
| 프론트엔드 | React (Vite), TypeScript |
| AI | Spring AI + Ollama (qwen2.5:1.5b), Anthropic API (Claude Haiku) |
| 인프라 | AWS EC2, Docker Compose, GitHub Actions CI/CD, Vercel |
| 연동 | Google Sheets API (Service Account) |

## 기대 효과

| 영역 | 기대 변화 |
|------|-----------|
| **운영 비용** | 뽑기판·칠판·거치대 제작·이동 비용 제거, 외부 설문 툴 구독 불필요 |
| **처리 속도** | 수기 확인 단계 자동화로 대기 시간 단축, 1회 행사당 리드 수집량 증가 |
| **이벤트 횟수** | 준비 부담 감소로 일 2회 → 3회 이상 운영 가능 |
| **리드 품질** | 무효 데이터 자동 차단 + AI 자동 분류로 영업 팀 후속 조치 즉시화 |
| **데이터 통합** | 설문·추첨·리드 데이터가 하나의 DB에 연결, 행사 후 별도 정리 불필요 |
| **현장 인력** | 경품 재고·참여자 확인·결과 기록 자동화로 운영 스태프 최소화 |
| **확장성** | 소규모 부스부터 대형 행사까지 추가 비용 없이 동일 시스템 재사용 |
